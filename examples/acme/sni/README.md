# Отдельные сертификаты через SNI

Пять TOML-примеров используют один listener и два сертификата:
`main` для `example.com` и `*.example.com` через Cloudflare,
`other` для `other.net` через Route 53. Внешние конфиги показывают несколько
имён одного виртуального хоста с разными сертификатами.

Замените домены, email и DNS-провайдеры. Скопируйте `cloudflare.env.example`
в `cloudflare.env`, `route53.env.example` в `route53.env` и задайте свои
учётные данные. Эти `.env` файлы исключены из git. Ограничьте права чтения
пользователем сервера. Если оба домена используют одного провайдера, задайте
его код обеим записям и используйте отдельные env-файлы при разных аккаунтах.

Примеры включают staging и `accept_terms=false` для каждой записи.
После настройки измените оба значения на `true`; для production удалите
staging directory в обеих записях.

```sh
mise run build
mise exec -- zig-out/bin/zhttpd -t -c examples/acme/sni/nginx.toml
mise exec -- zig-out/bin/zhttpd -c examples/acme/sni/nginx.toml
```

Для другого режима выберите соответствующий TOML. Все примеры слушают 443;
запускайте один за раз. DNS-01 не требует входящего TCP 80.
Обновления сертификатов выполняются независимо и последовательно;
неудача продления одного сертификата сохраняет действующий TLS и не отключает другие.

[Настройки, SNI-приоритет и правила reload](../../../docs/configuration.md#отдельные-сертификаты-и-sni).
